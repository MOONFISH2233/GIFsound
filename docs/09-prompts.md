## 1. 非浏览器播放器（手机 / 桌面）的差异

```
背景事实（已由实验确认，可直接采信）：
- 在 Chromium 151 与 Firefox 153 上，对动画 GIF 调用
  ctx.drawImage(img) 和 createImageBitmap(img)，拿到的永远是第 1 帧，
  但屏幕上确实在动画。
- 在 WebKit（Playwright 的 Windows 自编译版）上，createImageBitmap
  返回的是当前帧（连续取样得到 23,25,27,29,31,33,35）。
- 同一页面里，<video> 有 currentTime 和 requestVideoFrameCallback，
  CSS 动画有 getAnimations()[0].currentTime，都能读到播放位置。
- 结论：动画图像的帧可观测性在 HTML 规范中未定义，引擎实现分裂。

我的问题：**浏览器之外的播放环境，情况会不会不同？**
请逐个核实并给出官方文档/源码出处：
1. iOS：UIImageView 的 animationImages 与 animatedImage(with:duration:)
   是否保留每一帧自己的 delay？还是只用一个总时长平均分配？
   有没有「当前第几帧」的回调或属性？
2. Android：AnimatedImageDrawable（API 28+）有没有帧回调、能否读当前帧索引、
   能否控制播放进度？ImageDecoder 能否读到每帧 delay？
3. 桌面：Windows 照片、macOS 预览、VLC、QuickTime、GIMP、Photoshop
   对逐帧 delay 的处理是否一致？
4. ffmpeg / ImageMagick / gifsicle 重新编码 GIF 时，逐帧 delay 和
   自定义 Application Extension 分别是否幸存？
5. 手机相册（iOS Photos / Android 相册）播放 GIF 时是否保留原时序？

输出要求：分平台小节 + 一张汇总表
（平台 | 遵守逐帧 delay | 有当前帧回调 | 扩展块处理 | 来源URL），
并单列「未找到权威来源」的条目。不要写代码。
```

## 2. 呈现延迟测量（可独立成文的技术点）

```
背景：在浏览器里用 requestAnimationFrame 逐帧绘制 canvas，
同时用 Web Audio 播放音频。发现画面系统性落后音频约 26ms：
帧在第 T 个 rAF 回调里画，用户要到 T+合成器延迟才看到，
而音频按时间轴准点播放。用固定 27ms 提前取帧补偿后，平均滞后降到 4.4ms。

我的问题：**这个呈现延迟到底由什么决定，能不能自适应估计？**
请帮我设计一个可复现的测量方案，并回答：
1. 如何在纯浏览器内测量「帧被绘制」到「帧被呈现」的延迟？
   （可用的 API 有哪些？requestVideoFrameCallback 只对 <video> 有效，
    canvas 有没有等价物？）
2. 这个延迟在 60Hz / 120Hz / 144Hz 下如何变化？与 vsync 对齐有关吗？
3. Chromium / Firefox / WebKit 的差异有多大？
4. 有没有现成的学名或文献？（输出/呈现延迟 vs 输入延迟，
   input latency 研究很多，output/presentation latency 相对少）
5. 自适应估计方法：能否用「观察到的帧切换时刻」反推延迟？
   存在什么偏差（测量本身会引入延迟）？

输出要求：一份可执行的实验设计（变量、对照组、指标、样本量），
加一段不超过 300 字的「这块相对输入的已有研究，空白在哪里」的判断。
```

## 3. 动画图像帧时序指纹（新专利方向候选）

```
背景：GIF 的每一帧有一个 delay 字段（单位 1/100 秒），
这些 delay 组成一个序列，比如 80,100,120,60,140,100,90,110 ms。
实测（ffmpeg 重新编码）表明：**逐帧 delay 序列在重编码中被完整保留**，
而像素内容会被彻底改变；自定义的 Application Extension 则会被剥离。

我的想法：既然像素抗不住转码、容器扩展抗不住重编码，
那「帧时序序列」会不会是一个更鲁棒的隐蔽信道 / 指纹载体？

请帮我评估并检索：
1. 有没有已有工作把 GIF 的帧延迟序列当作水印 / 指纹 / 隐蔽信道？
   （检索：GIF frame delay steganography、covert timing channel animated image、
   帧延迟 隐写 水印。已知中国专利 CN107103630B 把 GCE 属性做区间映射编码，
    请核实其权利要求与法律状态。）
2. 工程可行性：常见链路（gifsicle -O3、ImageMagick、社交平台转码）
   对 delay 序列的保真度如何？会不会被归一化到整 10ms？
   会不会因为丢帧/合并帧而使序列错位？
3. 感知约束：delay 的改动在多大范围内不可察觉？有没有相关文献？
4. 容量估算：一个 N 帧的 GIF，若每帧 delay 可取 K 个「安全」值，
   可靠容量是多少比特？

输出要求：一段可行性判断（能/不能/有条件），加一份「若要投稿该投哪个方向」
的建议，加检索到的文献清单（带 URL）。
```

- drawImage() 三家都返回首帧

- 同页面里 <video> 有 currentTime 和 requestVideoFrameCallback，
  CSS 动画有 getAnimations()[0].currentTime

我的问题：**这处空白应该怎么提、向谁提、用什么形式提？**
请帮我：
1. 查证 whatwg/html、w3c/csswg-drafts、whatwg/webidl 等仓库里
   是否已有相关 issue（关键词：animated image current frame、
   image animation time、HTMLImageElement currentTime、
   createImageBitmap animated）。给出 issue 编号与状态。
2. 判断这属于哪个规范的管辖范围（HTML 的 <img>、WebIDL 的

## 5. 感知实验设计（论文必需）

```
背景：我们做的是「动画 GIF + 音频」的音画同步。
实测误差：在最优锚点下 P95 为 110ms、最大 140ms；
自绘方案不补偿时系统性滞后 26ms、补偿后 4.4ms。
我们想验证「多大的偏移会被用户察觉」，但不想直接引用 ITU-R BT.1359
（那是视频的阈值，短循环动画未必适用）。

我的问题：设计一个可执行的感知实验。
1. 方法选 ABX、2AFC 还是调整法？为什么？
2. 刺激材料：4 秒循环动画 + 有强节拍的音频（比如每秒一次的咔哒声），
   帧率 10fps（每帧 100ms）。这样的材料能分辨多小的偏移？
   会不会因为帧太粗糙而无法测出真实阈值？
3. 需要多少被试？组内还是组间？
4. 偏移量的搜索范围与步长（例如 -200ms 到 +200ms，步长 10ms）？
5. 如何控制「被试盯着看的是节拍点」这一注意因素？
6. 结果如何统计（psychometric function 拟合？90% 正确率对应阈值？）
7. 伦理与知情同意方面需要准备什么？

输出要求：一份完整的实验方案（含材料清单、流程、时长估算、统计方法），
加一段「这个实验若做不好，最可能被审稿人攻击的点」。

## 7. 论文投稿定位

```
我有一篇测量类论文，核心内容：
1. 三个浏览器引擎 × 三种动画图像格式（GIF/APNG/WebP）的帧可观测性实验。
   结果：drawImage 三家都返回首帧；createImageBitmap 仅 WebKit 返回当前帧。
   结论：规范未定义，引擎分裂，无移植性。
2. 对照实验：同页面里 <video> 和 CSS 动画都能读到播放位置。
3. 代价量化：以 img.onload 为锚点的延迟模型，帧错配率 10%（Chromium）
   /14%（Firefox），P95 误差 110ms；即使给 oracle 相位，Firefox 仍 4% 错配。
4. 一个自绘替代架构：切换延迟 26ms，可补偿到 4.4ms，中途切入精确。
5. 分发链路：ffmpeg 重编码保留逐帧 delay 但剥离自定义扩展。

我的问题：这篇文章最适合投哪里？
请评估：
1. 这个贡献体量适合 full paper、short paper 还是 workshop？
   不要安慰我，直接说。
2. 候选venue 排序（含投稿截止时间的大致规律）：ACM MMSys/NOSSDAV、
   WWW、IMC、CHI/ASSETS、IEEE ICME、Web 相关 workshop。
   每项给出「为什么匹配 / 为什么不匹配」。
3. 这篇文章最可能被拒的理由是什么？（审稿人会问什么）
4. 在投稿前，最低限度还要补哪些实验？（按性价比排序）
5. 有没有可能被归类为「negative result」而被低估？如何写法上规避？
```

## 8. 如果想找「能授权的专利」，换什么题

```

剩下只有很窄的工程细节，授权前景差。

我的问题：**在这个技术积累下，有没有更容易授权的邻近选题？**
我们已有的技术资产是：
- 一个自研的 GIF 解码器（LZW + 帧合成）与编码器
- 一套以「合成器截图 + 帧号条码」为真值的浏览器时序测量方法
- 实测数据：三引擎的帧可观测性差异、呈现延迟 26ms、播放器周期抖动
- 一个「单时钟驱动画面与音频」的播放器实现

请帮我：
1. 列出 5 个可以由这些资产自然延伸、且**技术问题更具体、更容易写出技术效果**
   的专利选题（不要泛泛的「一种多媒体播放方法」）。
2. 对每个选题，用一句话写出「要解决的技术问题」，一句话写「区别技术特征」。
3. 指出哪些选题更偏「装置/系统」（中国实践下客体风险更低）。
4. 不要编造专利号；如果要举现有技术，只能举你能确认存在的。

- **6** 是「决定要不要花钱申请专利」，建议在找代理师之前做完
