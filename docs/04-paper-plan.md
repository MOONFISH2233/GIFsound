> 定位调整：原计划写「我们实现了一个有声 GIF」。检索后这个定位站不住

>
> **改成一个测量研究**：「在遗产动画格式上，跨模态同步到底能不能做到确定性？
> 边界在哪里？」——这个问题目前**没有人系统回答过**，而且现有数据已经能支撑。

## 1. 核心主张（Contribution）

1. **一处规范空白 + 跨引擎行为分裂**：动画图像（GIF / APNG / 动画 WebP）的当前帧
   在 HTML 规范中**没有定义可观测性**。实测三家引擎：

   | 引擎 | `drawImage` | `createImageBitmap` |
   |---|---|---|
   | Chromium | 首帧 | 首帧 |
   | Firefox | 首帧 | 首帧 |
   | WebKit | 首帧 | **当前帧** |

   后果不是「无法观测」，而是**「没有可移植的观测手段」**——同一段代码换引擎静默失效。
   这是整篇论文最硬、最容易验证的贡献。

2. **量化这一不可观测性的代价**：以页面唯一可获得的锚点（`img.onload`）为时钟，
   延迟累积模型在 60fps 采样下的帧级错配率为 **10.0%**，P95 绝对误差 **110 ms**，
   最大 **140 ms**；而给予 oracle 相位时误差恒为 **0**。
   —— 差距完全来自「相位不可观测」。

3. **一个可行但需要付出代价的替代架构**：自绘渲染器 + 单一时间轴。
   实测帧切换滞后平均 **26.02 ms**、最大 **32.82 ms**，可通过**呈现延迟预测**补偿到平均 **4.43 ms**。
   热切入精确（偏移落在当前帧窗口内）。

4. **一个负面结果**：元素被 `display:none` 隐藏 2 秒后恢复，原生播放仅落后 **7.52 ms**，
   即 Chromium 不会因此暂停动画。**不要把「切后台必然失步」写进论文。**

> 第 1 与第 2 点是本文最硬的部分：它是**可验证的事实**，不依赖任何方案优劣的论证。

## 3. 结构

### 1. Introduction
- 背景：GIF 是唯一仍然广泛流通、但完全没有音频能力的遗产动画格式
- 问题：浏览器自动播放策略使「音频与动画同时开始」不可能，必然热切入；而热切入需要知道当前位置
- 贡献列表（上述 4 条）

### 2. Background & Related Work
- GIF89a 的 Application Extension 机制
- 三条既有路线：像素域隐写（Djaziri-Larbi 2016）、自建容器（CN105261054A，已驳回）、扩展块（Habr 2012 / audiogif 2019 / gifed 2023 / SoundGIF 2026）
- **必须引用并明确区分 gifed 2023 与 SoundGIF 2026**，否则会被认定隐瞒现有技术
- 说明本文不问「能不能装音频」，而问「装了之后能不能确定性同步」

### 3. 可观测性实验 ★
- 3.1 方法：条码帧号 + 合成器截图真值 + 三种媒体对照
- 3.2 结果：`drawImage` 三家都返回首帧；`createImageBitmap` 仅 WebKit 返回当前帧
- 3.3 讨论：规范空白 + 引擎分裂 → 无可移植观测手段（而不是「完全不可观测」）
- 3.4 对照：`<video>` 与 CSS 动画都有规格化 API，证明渲染管线做得到

### 4. 原生播放器的时序刻画
- 周期精度：3999.95 ms（标称 4000），标准差 0.25 ms
- **论点**：原生播放器**很准**——问题不在速率，在相位
- B1-oracle vs B1-realistic 的对比表
- 负面结果：隐藏元素不失步

### 5. 帧锚定扩展 + 自绘播放器
- 协议设计（简短，因为不是主要贡献）
- 与 gifed 2023 的差异说明
- 呈现延迟的测量与补偿
- 热切入的精确性

### 6. 讨论
- 什么时候该用哪种架构
- 兼容性代价：放弃 `<img>` 原生渲染，换确定性
- 扩展块被剥离的现实风险

### 7. Limitations
- 单浏览器（Chromium）、无头模式、合成素材、无感知实验
- 见技术报告 §7，**一条都不能省**

## 6. 写作纪律

1. **不许写「首次」**。gifed 2023、Habr 2012、SoundGIF 2026 都在。
2. **不许把「切后台失步」当结论**。实测不支持。
3. **「帧锚定」这个词要谨慎使用**。gifed 2023 草案已用类似结构，先引用再区分。
4. **B1 的对比条件要写明**：测试页只有一个 `<img>`，这对 B1 是最有利的条件，真实页面会更差——但这一点本项目**没有测**，只能作为 limitation 或 future work 提及。
5. 所有数字都要能追溯到 `results/*.json`。
