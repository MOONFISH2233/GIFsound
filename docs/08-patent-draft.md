# 一、权利要求书（素材）

**1.** 一种动画图像与音频的同步播放方法，其特征在于，包括：

由播放端读取动画图像文件，所述文件中包含多个音频数据块，每个音频数据块
在所述文件内关联所述动画图像的帧时序信息；

由所述播放端维护一条播放时间轴，并由所述播放端自身的渲染管线逐帧绘制所述动画图像，
而不依赖所述动画图像的原生播放状态；

在时刻 T，根据所述渲染管线的呈现延迟估计值 L，选择所述播放时间轴上 T+L 时刻
所对应的帧进行绘制，使该帧实际呈现的时刻与音频在 T+L 时刻的播放位置对齐；

当所述动画图像在音频被启用之前已开始播放时，根据所述播放时间轴的当前位置
计算音频切入偏移，并使音频从所述偏移处开始播放。

**2.** 根据权利要求 1 所述的方法，其特征在于，所述帧时序信息包括帧索引与呈现时间戳，
且所述多个音频数据块中的每一个关联至少一个帧索引。

**3.** 根据权利要求 1 所述的方法，其特征在于，所述呈现延迟估计值 L 由以下方式之一确定：
测量最近 N 次帧切换的实际呈现时刻并取统计量；或取所述播放端刷新周期的整数倍。

**4.** 根据权利要求 1 所述的方法，其特征在于，还包括：

解析所述文件中的映射描述数据，得到帧数、播放周期总长与音频字节长度；
将所述帧数与所述文件中实际解析出的帧数比对，将所述播放周期总长与各帧延迟之和比对，
将所述音频字节长度与实际读取到的音频字节数比对；
三者中任一不符时，判定帧-音频映射已失效，并转入无声播放。

**5.** 根据权利要求 1 所述的方法，其特征在于，音频按所述播放周期分段调度，
每个周期单独确定一次音频起播时刻，使调度误差不跨周期累积。

**6.** 根据权利要求 1 所述的方法，其特征在于，当音频因浏览器自动播放策略
而必须由用户手势启动时，在所述用户手势的回调中：
读取所述播放时间轴的当前位置 P；将音频的起播偏移设为 P；
使音频自所述偏移处开始播放，同时画面不中断、不回退。

**7.** 根据权利要求 1 所述的方法，其特征在于，所述文件为 GIF89a 格式，
所述多个音频数据块被承载于所述 GIF89a 的 Application Extension 中。

**8.** 根据权利要求 1 所述的方法，其特征在于，当所述帧-音频映射不可用，
或所述 Application Extension 被剥离时，所述播放端回退为原生渲染并静音播放。

**9.** 一种动画图像同步播放装置，包括：

解析模块，用于读取动画图像文件并解析其中的音频数据块与帧时序信息；
渲染模块，用于由自身渲染管线逐帧绘制所述动画图像；
调度模块，用于维护播放时间轴，并按呈现延迟估计值提前选择待绘制的帧；
音频模块，用于根据所述播放时间轴的当前位置确定音频切入偏移并调度音频播放。

**10.** 一种计算机可读存储介质，其上存储有计算机程序，所述程序被处理器执行时
实现权利要求 1 至 8 中任一项所述的方法。

# 二、说明书（素材）

## 技术领域

本发明涉及计算机图形与多媒体播放，具体涉及一种在动画图像上进行音频同步播放的
方法、装置及存储介质。

## 背景技术

动画图像（如 GIF、APNG、动画 WebP）被广泛用于即时通信与网页。其格式本身不含音频。
已有技术提供了若干把音频放入文件的方案：

- 在帧像素中做隐写（Djaziri-Larbi 等，2016），容量受图像内容限制，且需专用提取器；
- 把图像与音频打包进自建外层容器（CN105261054A，已驳回），无帧级时序；
- 在 GIF89a 的 Application Extension 中写入音频（audiogif，2019），
  但未定义音频与帧的对应关系，播放时由播放器按音频总时长平均摊派；
- 在 Application Extension 中定义与帧关联的音频控制块（gifed 草案，2023），
  但仅停留在格式定义，未给出播放端的同步方法。

上述方案共同存在一个未被解决的问题：**播放端无法确定当前显示的是第几帧。**

本申请的发明人在三个浏览器引擎上实测发现：`drawImage()` 对动画图像在三个引擎中
均只返回首帧；`createImageBitmap()` 在 Chromium 与 Firefox 中返回首帧，
仅在 WebKit 中返回当前帧。即该行为在规范中未被定义，各引擎实现不一致，
播放端无法获得可移植的帧位置信息。

在无法获得帧位置的前提下，若以 `img.onload` 为锚点、按各帧延迟累加推算当前帧，
实测（Chromium 151）帧级错配率为 10.0%、P95 误差 110 ms、最大 140 ms；
（Firefox 153）错配率 14.0%，且即使给定最优锚点仍有 4% 错配、最大 140 ms。
该误差已超过音画同步的可感知阈值。

此外，浏览器自动播放策略要求音频必须由用户手势启动，而动画图像自页面加载起即在播放，
因此「音频与动画同时开始」在真实场景中不成立，必须进行中途切入。
中途切入要求已知当前播放位置，而上述方案均无法提供。

## 发明内容

本申请的目的在于提供一种在无法观测原生播放状态时，仍能实现确定性音画同步的
播放方法与装置。

技术方案包括三个相互配合的环节：

**（一）由播放端拥有渲染时钟。** 播放端不依赖动画图像的原生播放，而是自行解码、
逐帧绘制，并以自身维护的时间轴同时驱动画面与音频。由此，当前播放位置成为
播放端自身可读的状态，而非不可观测的外部状态。

**（二）呈现延迟补偿。** 帧在渲染回调中被绘制，但要经过合成器延迟才被用户看到；
音频则按时间轴准点播放。若不补偿，画面将系统性落后音频约一个刷新周期。
本方案在时刻 T 选择时间轴上 T+L 时刻对应的帧进行绘制，其中 L 为呈现延迟估计值。

**（三）基于已知位置的中途切入。** 音频因自动播放策略而必须由用户手势启动时，
读取时间轴当前位置 P，令音频自偏移 P 处开始播放。画面不中断、不回退。

进一步地，方案对文件中的映射描述数据做三项交叉校验（帧数、周期总长、音频字节长度），
任一不符即判定映射失效并转入无声播放，从而在文件被重编码后具备可检测的降级能力。

## 有益效果

1. 在规范未定义帧可观测性的现状下，提供了可移植的确定性同步路径。
2. 呈现延迟补偿将帧切换滞后从实测平均 26.02 ms 降至 4.43 ms。
3. 中途切入的音频偏移可精确落入当前帧的时间窗内（实测 1601.2 ms 落入 [1600, 1680) ms）。
4. 映射失效可被检测，避免静默错位。

# 三、给代理师的说明

## 与最接近的现有技术的区别

| 现有技术 | 区别 |
|---|---|
| gifed 2023 草案 | 该草案只定义文件结构（ACE/ADT 块、百分之一秒时基），**未涉及播放端如何同步**；本方案的区别特征全在播放端 |
| SoundGIF 2026 | 该方案以音频时钟为主、每 250 ms 反馈校正、偏差超 80 ms 才 seek；本方案为**前馈**：由播放端时间轴直接决定取哪一帧，并做呈现延迟预测 |
| CN110505511B | 该专利在浏览器侧用「当前帧索引 / 总帧数 × 音频时长」换算，**仍以帧索引可读为前提**；本方案恰恰针对帧索引不可读的情形 |
| Djaziri-Larbi 2016 | 像素域隐写，需专用提取器；本方案为容器扩展 + 自绘播放 |
